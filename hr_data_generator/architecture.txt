HR DATA GENERATOR - ARCHITECTURE OVERVIEW

Purpose
-------
This project generates a realistic, configuration-driven HR data set for an
Azure SQL database and a Power BI semantic model. It supports a full historical
simulation and weekly incremental updates.

Simulation state
----------------
The in-memory state is a dictionary of pandas DataFrames. It is the contract
between simulators and the SQL writer. `simulation_state` in SQL stores the
last completed ISO year and week for incremental processing.

Core reporting model
--------------------
Dimensions include:

- dim_employee, dim_department, dim_role and dim_manager
- dim_hire_source, dim_education and dim_location
- dim_absence_type, dim_ploegendienst, dim_satisfaction_band and
  dim_engagement_band
- dim_satisfaction_driver, dim_performance_driver and dim_engagement_driver
- dim_salary_band, dim_salary_scale, dim_event_type and dim_reden_vertrek

Facts include:

- fact_employment: employment-event history; promotions, transfers, salary
  reviews and exits create or complete employment records. It stores relevant
  experience at the event start; cross-domain transfers retain only the
  configured share.
- fact_workforce_snapshot: one active employee per month-end. This is the
  primary source for workforce trends, salary, performance, satisfaction,
  engagement, current relevant experience, capacity and employee-month
  absence metrics.
- fact_absence: absence and leave episode events. It stores workday and hour
  values plus the employment, pay and satisfaction context at episode start.
- fact_vacancy and fact_recruitment: vacancy lifecycle and all applications.
  The accepted application determines the hire source of a filled vacancy.
- fact_salary_benchmark: monthly role, scale and salary-step benchmarks.
- fact_manager_assignment: effective-dated manager history used to build the
  monthly workforce context.
- fact_performance_review: annual performance-review events with one dominant
  performance driver.

Modeling principles
-------------------
- Facts are not directly related to one another in Power BI.
- Shared dimensions filter facts with single-direction relationships.
- fact_workforce_snapshot is employee-month grain and includes zero absence
  employees. Use it for denominators and employee trend measures.
- fact_absence is episode grain. Use it for absence-type filtering and
  episode-level analysis. `Duur_dagen` is calendar duration; workday and hour
  fields are preferred for capacity and verzuim metrics.
- Satisfaction is time-varying. `SatisfactionBand_Key` is therefore stored on
  the workforce snapshot, on absence episodes at their start date, and on exit
  events at their departure date.
- Engagement is a separate time-varying score on the workforce snapshot and
  exit events. Voluntary constructive contribution signals feed both its score
  and its dominant driver; satisfaction, relative pay, manager, performance
  and career momentum remain bounded context. Its effects on future performance
  and attrition are deliberately capped.
- Performance excludes absence, overtime and out-of-hours availability. Its
  drivers describe bounded, role-relevant execution, experience, collaboration,
  initiative or knowledge sharing.
- `role_career_paths` is the configuration-owned source for relevant education
  and promotion targets. `dim_role` exposes both lists; promotions use only
  configured targets, while transfers remain separate lateral moves.
- Time to fill is defined for closed vacancies. For hire-source analysis, use
  the accepted recruitment record's Vacancy_Key in a DAX TREATAS measure.

Operational notes
-----------------
- The HTTP endpoint uses HR_SIMULATION_MODE to select full or incremental.
- The timer trigger always uses incremental mode.
- Run a full simulation after adding snapshot columns or driver keys; an
  incremental run does not backfill existing snapshot rows.
- Local Azure Functions timer support requires Azurite through
  AzureWebJobsStorage=UseDevelopmentStorage=true.
- A full run is required after historical-logic or reporting-schema changes.
- The SQL writer manages table creation, additive columns, retired tables,
  primary keys, foreign keys, indexes and retention.
